# Integración experimental de descarga directa

La sección Descargar encola una URL directa HTTP/HTTPS, nombre y carpeta elegida. La sección Cola muestra estados persistentes, permite iniciar una tarea FIFO, cancelar tareas pendientes y reencolar tareas fallidas o interrumpidas. El controlador recupera estados running como interrupted al abrirse, y permanece activo al cambiar de página. Motor y cola conservan las políticas de seguridad existentes. Se advierte antes de encolar nombres con extensión ejecutable frecuente, sin pretender detectar todo código ejecutable.

La UI ahora muestra progreso e incluye un modo de pausa cooperativa opcional. No implementa cancelación activa, diagnóstico específico ni procesamiento automático. No descarga páginas de plataformas, no resuelve redirecciones ni extrae vídeos/audio, y limita a 1 GiB. Solo un proceso/instancia por base. URLs, incluso parámetros, se guardan en texto claro; la UI lo advierte. La ubicación destino debe ser confiable. No ejecutar archivos desconocidos.

**Prototipo no apto para producción**: siguen pendientes auditoría SSRF, protección frente a carreras y enlaces simbólicos, publicación atómica, recuperación frente a caída, limpieza de parciales, verificación de funcionamiento en Windows y revisión de licencias. No se ha publicado ni enlazado el nuevo ejecutable desde la web.

## Progreso y pausa en interfaz
En Cola se puede habilitar el modo con pausa antes de iniciar una tarea. Requiere longitud conocida y ETag fuerte, tanto al comenzar como al reanudar. Si no se cumple, la tarea falla sin cambio automático de modo; se puede reencolar y probar el modo normal. Durante la descarga se muestra progreso aproximado por bytes de red; con longitud desconocida el indicador es indeterminado. La pausa es cooperativa y se atiende cuando llega un chunk; no detiene inmediatamente una conexión o lectura bloqueada. Para continuar hay que reencolar con Reintentar e iniciar de nuevo. La transición de estado ocurre solo después de guardar el checkpoint.

Los parciales se guardan bajo el directorio de datos de la aplicación usando path_provider y no se eliminan automáticamente, incluso al completarse; pueden contener datos sensibles. El sistema de archivos y SQLite no se actualizan atómicamente; tras una caída puede quedar un parcial o destino incompleto o un checkpoint obsoleto, y se requiere comprobación manual. El modo normal no tiene pausa y no genera checkpoints. Una sola instancia y carpeta de datos confiable; no se ha auditado la seguridad ni probado interactivamente Windows.

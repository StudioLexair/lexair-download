# Pausa cooperativa experimental

`DownloadQueueWorker.runNextPausable()` inicia una transferencia con tamaño conocido y ETag fuerte; recibe un `PauseRequest` y callback opcional de progreso. La aplicación puede llamar a `request()` mientras la transferencia está activa. El trabajador termina de recibir el chunk actual, guarda el parcial y su hash y registra el checkpoint con estado `interrupted`. Reencolar mediante `retry(id)` y llamar a `runNext()` para reanudar. Si la transferencia termina antes de procesar la solicitud, se comprueba y publica como completada. La transferencia pausable sin solicitud también termina normalmente.

La pausa es cooperativa: no interrumpe una operación de conexión ni una lectura bloqueada inmediatamente; se atiende tras recibir un chunk y depende de los timeouts de red. No hay botón ni integración UI. La descarga normal `runNext()` no admite pausa ni checkpoints automáticos, y la reanudación también puede pausarse usando `runNextPausable`; se actualiza el checkpoint después de agregar el sufijo. La fuente debe ofrecer tamaño y ETag fuerte; sin ellos, el flujo pausable falla, no cambia automáticamente al normal. El estado de pausa reutiliza `interrupted` y no distingue pausa intencionada de corte inesperado.

Antes de un inicio de la aplicación, con el único proceso/trabajador detenido, `recoverInterrupted()` convierte `running` a `interrupted`; si existe checkpoint, el usuario puede reencolarlo. Un corte inesperado antes de guardar un checkpoint no permite reanudar lo recibido. La base y la carpeta de parciales deben ser privadas y confiables; sin sincronización entre procesos ni protección contra modificaciones concurrentes.

No hay fsync, checkpoint periódico, publicación atómica, limpieza automática de parciales, rollback seguro ante corte de energía ni UX para decidir qué hacer con un destino existente. Una caída durante la unión o publicación puede dejar un parcial incompatible o un destino incompleto; no se declara completado por su mera existencia y se requiere revisión manual. Tras completar se conservan los parciales y sus metadatos. La función aún no es apta para producción. Ver `checkpoints-cola.md` y `reanudacion-experimental.md` para más detalles.

## Pausa durante reanudación
En `runNextPausable`, una tarea con checkpoint abre un 206 con Range/If-Range, recibe el sufijo a un archivo temporal y, al solicitar pausa, calcula el hash de prefijo más sufijo y agrega los bytes. Después actualiza el checkpoint y el estado en una transacción condicionada al checkpoint anterior. Al volver a encolar se empieza desde la nueva posición. Si se cae o falla tras agregar bytes y antes de guardar el nuevo checkpoint, el anterior no coincidirá: se rechaza el próximo intento y hace falta intervención manual; no hay atomicidad entre archivo y base. La pausa no interrumpe un socket bloqueado y no hay integración UI.
